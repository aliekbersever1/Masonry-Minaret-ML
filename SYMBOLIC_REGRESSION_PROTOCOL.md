# Symbolic regression: search settings and grouped validation

This document describes the symbolic-regression procedure implemented in [`regression_formulas_group_cv.py`](regression_formulas_group_cv.py) for the masonry-minaret natural-frequency study. It documents the current public code; it is not a record of a completed rerun or a claim of bit-for-bit reproducibility across computing environments.

## Dataset, inputs and targets

- Dataset: `data/minaret_frequency_database.xlsx` (1,146 finite-element realizations of 191 unique geometries).
- Targets: the first and second finite-element modal frequencies, `f1 (Hz)` and `f2 (Hz)`, fitted separately.
- Features: `H_m`, `D0_m`, `Dtop_m`, `t_m`, `B_kaide_m`, and `sqrt_E_div_rho`.
- **Critical units:** the released symbolic-regression script currently computes `sqrt_E_div_rho = sqrt(E_MPa / rho_kgm3)`, with **E in MPa**, not Pa. The numerical coefficients of fitted expressions depend on this convention. Do not silently replace this with `sqrt(1e6 * E_MPa / rho_kgm3)` without rerunning the symbolic-regression fits and updating the reported equations.
- Geometry groups are based on `(H_m, D0_m, Dtop_m, t_m, B_kaide_m)` rounded to eight decimal places.

## PySR expression search configuration

The code instantiates `PySRRegressor` with these explicit settings:

| Setting | Value |
|---|---|
| Binary operators | `+`, `-`, `*`, `/` |
| Unary operators | `sqrt`, `log` |
| Search iterations | `niterations=500` |
| Populations | `populations=12` |
| Maximum expression size | `maxsize=15` |
| Maximum expression depth | `maxdepth=6` |
| Parsimony coefficient | `parsimony=0.0001` |
| Constraints | `sqrt: 1`, `log: 1`, `/`: `(-1, 9)` |
| Nested constraints | `sqrt` cannot contain another `sqrt`; `log` cannot contain another `log` |
| Equation-selection option | `model_selection="best"` |
| Search acceleration | `turbo=True` |
| Random-state base | 42 |
| Custom early-stopping condition | None defined in this script; a budget of 500 iterations is specified |
| Loss | Default PySR loss (version-dependent default; verify against the recorded PySR version) |

The script does not perform a separate inner CV search over these PySR configuration parameters. The parameters are kept fixed for all outer folds.

## Geometry-grouped cross-validation: no equation-selection leakage

1. For each target independently, the script calls `GroupKFold(n_splits=5)`.
2. In each outer fold, the script checks that training and test geometry-group IDs do not overlap.
3. It instantiates a **new** `PySRRegressor` with `random_state=42+fold_number` (seeds 43 through 47).
4. **Both expression structure and numerical constants are fitted using the outer-training subset only**: `model.fit(X_train.to_numpy(), y_train.to_numpy())`.
5. Predictions on held-out geometries use this fold-specific expression. The published CV statistics should come from these held-out predictions, not from a full-data model.
6. After outer-CV evaluation, a separate final PySR search is performed on all 1,146 realizations with `random_state=42` to derive the displayed full-data equations. Those full-data equations are not used to produce held-out scores.

This is geometry-grouped **outer** CV for symbolic regression. Unlike the ensemble ML hyperparameter optimization, it is not a fully nested inner/outer CV procedure for PySR hyperparameter selection.

## Running the analysis

From the repository root in a compatible Python and Julia/PySR environment:

```bash
python -m pip install -r requirements.txt
python regression_formulas_group_cv.py --data data/minaret_frequency_database.xlsx --output results/regression
```

**This job can be computationally intensive:** it runs PySR discovery in five outer folds for each of two targets, plus one full-data discovery per target.
